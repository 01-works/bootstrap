# YW Paseo Cleanup

기기 전체의 Paseo 자원을 조사해 **끝난 것만** 정리한다. 기본 정리 단위는 에이전트이고, workspace와 디렉터리 제거에는 조건을 더 붙인다. 조사·분류·계획은 확인 없이 진행한다. 상태를 바꾸는 일은 사용자가 승인한 계획 범위 안에서만 한다.

이 문서는 Paseo 0.15.4에서 확인한 동작을 기준으로 한다. 데몬 버전이 다르면 아래 "버전" 규칙을 따른다.

## 왜 status만으로 판단하지 않는가

- `closed`는 끝났다는 뜻이 아니다. 런타임이 해제됐을 뿐이다. 기본 idle cleanup이 켜져 있고 보류할 작업이 없으면, 마지막 활동 뒤 1시간이 지나 해제될 수 있다. 프롬프트를 보내면 다시 살아난다.
- 다음 세 경우 모두 `idle`로 보인다.
  - 사용자에게 질문하고 멈춘 세션. Codex의 비동기 질문은 `pendingPermissions`에만 보인다.
  - 백그라운드 하위 작업을 기다리는 세션
  - heartbeat로 감독 중인 세션
- `requiresAttention`·`attentionReason`은 "사용자가 아직 안 봄"을 나타내는 표시다. 대기 중인지의 근거가 아니다.
- 보관(`archivedAt`)은 완료가 아니다. 보관된 세션에도 pending 질문이 남아 있을 수 있다.
- 다음 셋은 어느 것도 단독으로 완료 근거가 되지 않는다: PR 병합, 오래된 `updatedAt`, 부모의 완료.
- `get_agent_activity`와 앱의 타임라인 조회는 세션을 다시 로드한다. 일괄 조사에 쓰지 않는다.

## 시작: 범위·자기 보호·기록

- **범위:** 기본은 현재 호스트다. 다른 호스트는 사용자가 지정했을 때만 같은 절차로 따로 조사한다. 원격과의 관계는 보호 판단에는 넣되, 정리 범위를 원격으로 넓히지 않는다. 원격 workspace는 미커밋 변경을 확인할 수단이 없으므로 남긴다.
- **자기 보호:** 다음은 고정 제외한다.
  - 자신의 전체 agent ID와 그 조상·후손
  - 자신의 workspace와 cwd
  - 이 정리를 위해 띄운 조사·검토 세션

  백그라운드 서브에이전트를 기다리는 동안에는 자신도 `idle`·`finished`로 보인다는 점에 주의한다.
- **도구 제한:** 실행 환경의 상위 도구 제한을 따른다. 아래 실행 경로를 쓸 수 없으면 해당 동작을 보류하고, 보호 수준이 낮은 경로로 바꾸지 않는다.
- **실행 기록:** `${XDG_STATE_HOME:-$HOME/.local/state}/yw-paseo-cleanup/<실행 ID>/`에 남긴다. 디렉터리는 0700, 파일은 0600으로 두고 저장소에 커밋하지 않는다. 보고에 경로를 적는다. 남기는 파일은 다음과 같다.
  - 수집 결과: 처음 결과를 덮어쓰지 않는다.
  - `plan.md`: 분류, 승인 표, 계획 버전
  - `result.md`: 실행 내역과 readback
- **보호 기간:** 기본 **72시간**이다. 사용자가 실행마다 바꿀 수 있다. 기간을 바꿔도 다른 보호 조건은 그대로다.

## 읽기 전용 수집

수집기 `scan.mjs`(이 스킬 폴더)는 다음 자료를 **읽기만** 하고 분류 초안까지 만든다: Paseo 저장 레코드, git, gh, 감독 기록, provider 이력 파일. Paseo 데몬 API는 부르지 않는다. live 상태는 모델이 MCP로 조회해 파일로 넘긴다.

1. **저장소 일치 확인:** `list_hosts`로 현재 `serverId`를 확인한다. MCP 대상 호스트와 저장 파일을 읽는 호스트, 현재 데몬의 Paseo home(기본 `~/.paseo`, `PASEO_HOME`이 있으면 그 값)이 일치하는지 확인하고 경로와 시각을 기록한다. 저장소의 소속과 완전성을 확인하지 못하면, 그 자료만으로 관계·예약이 없다고 판정하지 않는다.
2. **MCP 조회:** `list_workspaces(includeBackground: true)`, `list_pending_permissions`, `list_terminals(all: true)`를 부르고 결과를 실행 디렉터리에 저장한다. 터미널은 전역 조회 한 번으로 모든 cwd를 관측한 것으로 넘긴다.
3. **live 상태 수집:**
   - workspace마다 cwd를 지정해 `list_agents(cwd, includeBackground: true, limit: 200)`를 부른다. cwd를 빼면 호출자 workspace만 보인다. 결과가 200개면 누락이 있다고 기록한다.
   - 보관된 workspace나 등록되지 않은 cwd에 남은 비보관 에이전트는 수집기가 저장 레코드에서 찾는다. 이들은 live 관측이 없어 판단 불가로 남고, 그 보호가 관계를 따라 조상·소속 workspace·경로로 전파된다.
   - 후보로 좁혀진 에이전트는 `get_agent_status`로 상태와 pending을 확인한다. 이 호출은 런타임이 없으면 저장값으로 답하므로, 결과가 "저장값 응답"일 수 있다고 기록한다.
   - 조회 결과를 실행 디렉터리에 저장한다. 형식은 `node scan.mjs --help`에 나온다. live·pending·terminals 입력에는 조회한 `serverId`, 관측 시각, 범위를 함께 적는다. 수집기는 호스트가 다르거나, 관측 시각이 없거나, 오래된 입력(기본 30분 초과)을 미확인으로 처리한다. 이전 실행의 입력을 다시 쓰지 말고, 실행할 때마다 새로 조회한다.
4. **수집기 실행:**

   ```sh
   node <이 스킬 폴더>/scan.mjs --out <실행 디렉터리> --self-agent <자신의 전체 ID> --self-cwd <자신의 cwd> \
     --live <live.json> --pending <pending.json> --terminals <terminals.json> --gh
   ```

   - **미확인:** 수집기나 입력으로 확인할 수 있었는데 확인하지 못한 조건이다. 관계·보호 자료의 `gaps`, PR 미조회, 그 cwd의 터미널 관측 없음, git 명령 실패가 해당한다. 미확인 조건이 있는 항목은 배치 승인 후보가 되지 않는다.
   - **남은 확인(`remainingChecks`):** 수집기가 원래 확인하지 않는 조건이다. 프로세스 사용, workspace script 실행 상태, teardown 내용과 영향, workspace ID 기준 터미널이 해당한다. 수집기의 터미널 판정은 cwd 기준이므로, workspace 후보에는 목록에 없더라도 workspace ID 기준 터미널 확인이 늘 남는다. 배치 승인 후보에 이 목록이 붙으며, 모델이 실행 직전에 모두 확인하기 전에는 A에 올리지 않는다.

5. **본문 발췌:** 보호와 완료 판정 상속으로 걸러 내고 남은 후보만 고른다. 고른 전체 agent ID 목록을 `--excerpt-ids`로 넘긴다. 불필요한 본문은 읽거나 저장하지 않는다. 새 출력 경로(예: `<실행 디렉터리>/excerpts`)를 주고 `--excerpts`를 붙여 다시 실행한다. 처음 결과는 그대로 둔다. 수집기는 provider 이력 파일(Claude transcript, Codex rollout)을 직접 읽는다. 찾지 못한 세션은 발췌 없음으로 남기고, `get_agent_activity`로 대신 읽지 않는다. 다른 에이전트가 보낸 요청(`<paseo-system kind="agent-message">`)도 요청으로 본다. 요청과 응답의 대응이 불확실하면 `pairUncertain`으로 표시된다.
6. **누락 확인:** 결과의 메타(호스트, 수집 시각, 옵션)와 `gaps`(파싱 실패, 명령 실패, 누락, 저장값 응답, 발췌 잘림)를 확인한다. 수집이 불완전한 범위는 판단 불가로 둔다.

수집기 출력은 허용한 필드만 담는다. 경로·ID 같은 구조 값에 비밀 패턴이 있으면 출력에는 `[STRUCT_SHA256:…]`로 표시된다. 분류는 원래 값으로 끝낸 결과이며, 그런 항목을 실행할 때는 저장 레코드나 git에서 원래 경로를 다시 읽어 해시와 대조한다. `~/.paseo/agents/*` 원본에는 토큰이 있으므로 복사하거나 대화·기록에 붙이지 않는다. 발췌한 본문에도 비밀이 있을 수 있으니 보고에는 필요한 만큼만 인용한다.

## 관계와 보호 범위

관계는 두 종류로 나눠 계산한다.

- **전파 관계:** `paseo.parent-agent-id`. archive가 실제로 연쇄되는 경로이며, [archive 전 공통 안전 대조](../yw-supervisor/references/archive-safety.md)의 후손 재귀 조회 대상이다.
- **보호 관계:** archive가 전파되지는 않지만 끊으면 안 되는 관계다.
  - 이어받기 체인: `zerosub.continued-from`·`handoff.from`·`agent-list.continued-from`
  - 완료 알림 구독: Paseo home의 `finish-subscriptions.json`. 라벨 없이 완료 알림만 기다리는 관계도 있다.
  - heartbeat 대상: `schedules/*.json`에서 `target.type: "agent"`인 항목. MCP `list_schedules`에는 나오지 않는다.
  - schedule의 cwd
  - yw-supervisor 기록(`tasks.md`)의 소유 관계

다음 신호가 있으면 보호한다. 보호는 관계를 따라 전파되어, 보호 대상의 조상과 구독자도 보호된다. workspace에 보호 대상 구성원이 있으면 그 workspace도 보호된다. **보관된 세션도 이 대조에서 빼지 않는다.**

| 보호 사유 | 신호 |
|---|---|
| 활성 | live `running`·`initializing`, 활성 턴 |
| 사용자 대기 | `pendingPermissions`(보관된 세션 포함), 또는 현재 요청을 끝내려면 답이 필요한 질문으로 끝난 발췌 |
| 작업 대기 | 다음 중 하나: 활성·대기 중인 후손, 완료 알림 구독, 기록에 적힌 백그라운드 대기·재개 조건 |
| 예약 대기 | active 또는 paused 상태인 heartbeat·schedule의 대상 |
| 최근 | 다음 중 하나가 보호 기간 안에 있음: 기준 시각(`lastUserMessageAt`, 없으면 `lastActivityAt`), 응답·인계·작업 결과 같은 의미 있는 활동. 필요한 시각이 없거나 출처가 불확실한 경우도 포함 |
| 감독 관리 범위 | 비보관 감독(chief 포함)이 지금 소유하거나 열린 감사·정리 범위로 관리하는 lane. 그 감독이 idle·질문 대기·heartbeat 대기여도 보호한다. 과거에 언급만 된 항목은 완료나 관리 종료가 명시됐는지 확인하고, 구분할 수 없으면 보호한다 |
| 허브 | 서로 무관한 lane과 대화가 쌓인 "홈" workspace. workspace는 남기고 안의 세션만 하나씩 본다 |
| 데이터 | 미커밋·untracked 변경, OPEN PR, 어디에도 보존되지 않은 커밋, 보존 가치가 있거나 판단할 수 없는 ignored 파일 |

이어받기 체인은 같은 라벨을 끝까지 따라간다. 최신 후임이 끝나지 않았으면 옛 세션도 보호한다. 다음 경우는 판단 불가로 둔다.

- 체인에 분기나 순환이 있다.
- 체인이 다른 호스트로 이어지는데 확인할 수 없다.

## 분류와 완료 근거

에이전트·workspace·디렉터리마다 세 축을 따로 기록한다.

- **작업 상태:** 활성 / 사용자 대기 / 작업 대기 / 예약 대기 / 완료 후보 / 판단 불가
- **보존 사유:** 위 표의 사유. 여러 개일 수 있다.
- **정리 판정:** 제외 / 항목별 결정 / 배치 승인 후보. 실행 단계에서는 승인됨 / 적용 확인 / 보류 / 부분 실패를 덧붙인다.

수집기가 내는 분류는 초안이다. 초안에서 `supervisor_scope`가 붙은 항목은 review로 나오지만, 계획에서는 C(감독 관리 범위)로 옮긴다. 경계 절의 세 조건을 확인한 것만 다시 검토한다. 배치 승인 후보(A)로 올리려면 아래 완료 근거와 "자원별 정리 조건"이 **모두 확인돼야** 한다. `gaps`, 명령 오류, provider 불가 등으로 확인하지 못한 조건은 충족한 것으로 치지 않는다.

**판단 순서**

1. 전체 메타데이터와 관계로 보호 대상을 먼저 걸러 낸다.
2. 남은 후보에 완료 판정 상속을 적용한다.
3. 상속 근거가 없는 후보만 본문 발췌를 읽는다.
4. 발췌로 판단할 수 없을 때만 범위를 넓혀 확인한다. 넓히는 수단은 그 세션 하나의 provider 이력 파일 전체(첫 요청부터의 모든 요청과 응답), 소유 감독 기록, 연결된 이슈·PR이다. 이력 파일은 대화 안에서만 읽고, 기록에는 판정 근거만 요약한다. `get_agent_activity`는 쓰지 않는다.

모든 세션의 본문부터 읽지 않는다.

**완료 판정 상속**

소유 감독이나 chief가 남긴 명시적 완료 판정이 그 작업·에이전트를 포함하면, 본문을 다시 판정하지 않고 그 판정을 이어받는다. 조건은 다음과 같다.

- 기록에서 판정자, 대상, 근거, 시각, 잔여 조치, 인계 여부를 식별할 수 있다.
- 판정 뒤에 새 요청, 후속 담당, 미해결 결과가 없다.
- 지금도 pending이 없고, 아직 보관되지 않은 활성 후손이 없다.

감독 체인이 보관됐다는 사실만으로는 상속하지 않는다.

**본문 판정**

상속 근거가 없는 세션은 마지막 사용자 요청과 그 대답인 마지막 응답을 함께 읽는다. 이 한 쌍은 검토의 시작점일 뿐이다. 그 응답이 앞서 남아 있던 요청·작업·백그라운드 대기까지 끝냈는지 확인한다.

- 부모 라벨이 없다고 사용자가 직접 연 대화라고 단정하지 않는다. 수동으로 만든 작업자, 분리된 세션, 라벨을 잃은 후임일 수 있다.
- 요청한 결과가 나왔고 필수 후속 조치가 없으면 **완료 후보**다. "원하시면 …" 같은 선택적 제안은 미완료로 보지 않는다.
- 요청을 끝내려면 답이 필요한 질문으로 끝났으면 **사용자 대기**다.
- 다음 경우는 범위를 넓혀 확인하고, 그래도 모르겠으면 **판단 불가**로 둔다.
  - 발췌가 잘렸다.
  - 요청과 응답의 대응이나 순서가 불확실하다.
  - 결과를 판단할 수 없다.
  - 발췌가 없다.
- 오래됐다는 이유로 판단 불가를 완료 후보로 올리지 않는다.

## 자원별 정리 조건

에이전트·workspace archive 후보나 이를 위한 detach를 판단하기 전에 [공통 안전 대조](../yw-supervisor/references/archive-safety.md)를 읽고 적용한다. 참조를 읽을 수 없으면 보류한다.

부모·workspace archive는 closed 후손도 연쇄 보관할 수 있으므로, 후손 전체·인계 체인에 범위 밖·미완료·소유 불명·필요한 알림 중계가 있거나 이를 확인할 수 없으면 보류하고, detach는 기존 권한 안에서만 하며 `--force`·MCP 우회는 금지한다. archive는 잎부터 하나씩 하고, 매 호출 직전에 미보관 후손이 0인지 확인한다. 각 archive 직후 대상과 영향받는 후손의 `Archived`·`ArchivedAt`·부모 관계를 다시 읽어 확인하고, 확인되기 전에는 다음 부모·workspace archive로 넘어가지 않는다. 부모 archive로 후손을 한꺼번에 정리하지 않는다.

workspace는 자기·살아 있는 감독의 작업 공간이 아니고, 모든 구성원의 완료·소유와 미커밋 변경·터미널 부재를 확인한 경우에만 archive한다. 확인할 수 없으면 보존한다. 감독 자체의 detach 동의는 그 감독 자신이나 사용자에게 받으며, 부모의 동의로 대신하지 않는다.

### 에이전트

다음을 모두 충족해야 한다.

- 완료 후보이고 보존 사유가 없다.
- [공통 안전 대조](../yw-supervisor/references/archive-safety.md)의 후손 전체가 같은 계획 안에서 완료·소유 확인됐다.
- 걸려 있는 heartbeat, 완료 알림 구독, 알림 중계가 없다.

archive하면 그 에이전트의 heartbeat에 완료 처리가 시도된다. 그래서 사용자가 요청한 감시가 걸린 세션은 정리하지 않는다.

보관된 세션은 정리 대상이 아니다. 표시된 status만 보고 런타임을 끄지(kill) 않고, pending이 관측되면 사용자 대기로 보고한다.

### workspace

다음을 모두 충족해야 한다.

- [공통 안전 대조](../yw-supervisor/references/archive-safety.md)의 workspace 추가 조건을 통과한다.
- 구성원은 MCP 목록과 저장 레코드의 `workspaceId`를 대조해 확정한다. 보관된 구성원도 보호 대조에 포함한다.
- 비보관 구성원이 모두 이번 계획에서 archive되고 readback까지 끝났다. 또는 비보관 구성원이 없다.
- 허브, schedule cwd, 감독 관리 범위가 아니다.
- 터미널과 실행 중인 workspace script가 없다. workspace archive는 cwd가 아니라 **workspaceId에 속한 터미널을 모두 종료**하며, 에이전트가 만든 터미널은 cwd와 상관없이 그 에이전트의 workspace에 속한다. 그래서 전역 `list_terminals`의 cwd 목록은 터미널이 없다는 근거가 되지 않는다. archive 직전에 workspace ID 기준(`paseo terminal ls --workspace <workspace ID> --json`)으로 확인한다. 이 조회를 쓸 수 없으면 그 workspace는 보류한다.
- 제거할 실제 경로를 다른 곳에서 쓰지 않는다. realpath와 경로 포함 관계로 다음을 확인한다: 자기 작업, 다른 workspace, 에이전트, schedule, 터미널·script, 관측 가능한 프로세스.

디렉터리 처리는 workspace 종류에 따라 다르다.

- **Paseo 소유 worktree:** archive하면 `git worktree remove --force`로 지워지고, 설정된 teardown 명령이 실행된다. 아래 "디렉터리 제거 공통 조건"도 충족해야 한다.
- **local 디렉터리 workspace:** 디렉터리는 남는다. 그래서 git·HEAD 조건은 적용하지 않는다. 구성원·보호 관계·터미널 조건은 확인하고, 구성원과 터미널에 대한 archive 효과는 따로 readback한다.

### 연결이 끊긴 worktree

활성 workspace에 연결되지 않은 `<Paseo home>/worktrees/*/*`가 대상이다. 다음을 모두 충족해야 한다.

- 소유 저장소의 `git worktree list --porcelain`에 등록된 정상 worktree이고 locked가 아니다.
- 경로를 다른 곳에서 쓰지 않는다. 다음 어디에서도 참조되지 않아야 한다: 비보관 에이전트의 cwd, 감독 기록, schedule, 터미널, 관측 가능한 프로세스. 비보관 에이전트의 cwd에 없다는 사실만으로 쓰지 않는다고 보지 않는다.
- 보호 기간 안에 의미 있는 수정이 없다. 루트 디렉터리 mtime이나 마지막 커밋 시각 하나만으로 판정하지 않는다. 수집기가 내는 시각은 관측한 몇 가지 시각(커밋, 루트, index, HEAD 파일) 중 가장 늦은 값일 뿐이고, 그동안 수정이 없었다는 증명은 아니다. 계획과 보고에 이 한계를 적는다. 확인할 수 없으면 판단 불가로 둔다.
- 아래 "디렉터리 제거 공통 조건"을 충족한다.

다음 디렉터리는 목록만 내고 이 스킬이 지우지 않는다.

- 깨진 worktree(gitdir 대상이 없음)
- git이 아닌 산출물 디렉터리
- 상위 저장소 안에 중첩된 경로

### 디렉터리 제거 공통 조건

Paseo 소유 workspace worktree와 연결이 끊긴 worktree에 모두 적용한다.

- **clean:** `GIT_OPTIONAL_LOCKS=0 git -C <경로> status --porcelain=v2 -z --untracked-files=all`이 성공하고 출력이 비어 있다. 명령이 실패하면 clean으로 보지 않는다.
- **HEAD 보존:** 다음 중 하나여야 한다.
  - HEAD가 기본 브랜치에 포함된다.
  - 그 브랜치의 MERGED PR `headRefOid`가 현재 HEAD와 같다. 병합 뒤 커밋이 더 있으면 보존된 것이 아니다.
  - DETACHED HEAD면 제거 뒤에도 남는 브랜치·태그에서 도달할 수 있다.
- **ignored 파일:** ignored 항목이 없거나, 재생성 가능 항목만 있어야 A에 넣는다. 재생성 가능한지는 저장소 기준 경로와 용도로 확인한다. 이름이 `dist`라고 해서 재생성 가능하다고 보지 않는다. 보존 가치가 있거나 판단할 수 없는 파일이 있으면 B로 보낸다.
- **teardown:** 실행 내용과 영향 범위를 확인해 계획에 넣는다. 확인할 수 없는 teardown이 걸린 workspace는 A에 넣지 않는다.

## 계획과 승인

`plan.md`에 계획 버전과 함께 다음 세 묶음을 쓴다.

**A. 배치 승인 후보**

완료와 영향 범위가 확인된 에이전트 archive, 조건을 통과한 workspace archive, 정상 worktree 제거가 여기에 들어간다. 항목마다 다음을 적는다.

- 호스트와 전체 ID, 실제 경로
- 동작과 영향받는 후손·관계
- 완료 근거와 확인 시각
- 지워지는 디렉터리와 ignored 경로, 남는 브랜치·기록
- heartbeat·schedule 영향과 teardown

**B. 항목별 결정**

사용자 결정이 필요한 것을 한 표에 모아 항목마다 고르게 한다. 다음이 여기에 해당한다.

- 보존 의사가 불명확한 대화, 사용자에게 답을 기다리는 질문
- 미커밋·ignored 산출물, 고유 커밋, DETACHED HEAD
- 예약의 종료·이전, 다른 소유자의 세션 분리

**C. 보존·판단 불가**

활성 lane, 감독 관리 범위, 허브, 데이터, 증거 부족 같은 사유별로 개수와 대표 ID를 적는다.

**승인 받기**

- 사용자에게 A·B를 보여 주고 승인을 받는다.
- 한 번 승인한 계획을 항목마다 다시 묻지 않는다.
- 승인 범위를 넓히지 않는다. "정리해 줘"를 데이터 폐기, 감시 종료, 진행 중 작업 중단의 승인으로 해석하지 않는다.

**B 결정의 효력**

B의 결정은 보존할지, 추가 작업을 어디까지 할지를 정하는 것이다.

- 결정으로 사실관계가 해소된 항목은 계획을 갱신하고 자원별 정리 조건을 다시 확인한다.
- B 승인만으로 A의 안전 조건을 건너뛰지 않는다.
- 이 스킬 범위를 넘는 조치는 별도 작업으로 구분한다. 미완료 작업 종료, 예약 변경, 다른 소유자의 세션 분리(detach)가 여기에 해당한다.
- 사용자가 폐기를 결정한 미완료 세션은 그 별도 작업의 결과로, "완료"가 아니라 "사용자 결정에 따른 종료"로 기록한다.

## 실행 순서와 직전 재확인

1. **실행 직전 재확인:** 승인된 계획과 현재 상태를 다시 대조한다.
   - 새 요청, 턴, pending, 오류
   - 후손·이어받기·구독의 추가와 변경
   - heartbeat·schedule
   - workspace 구성원과 터미널
   - git HEAD, 변경, untracked, ignored, 등록, 잠금
   - teardown 정의와 내용
   - 다른 정리 주체가 이미 바꾼 상태

   안전에 영향을 주는 차이가 있으면 **그 항목과 그 항목에 의존하는 부모·workspace만** 보류한다. 대상을 조용히 늘리지 않는다.
2. **에이전트:** 승인된 잎부터 하나씩 [공통 안전 대조](../yw-supervisor/references/archive-safety.md)의 archive 경로와 상태 변경 확인을 따른다.
   - 매 archive 호출 직전에, 아직 보관되지 않은 후손이 0인지 확인한다.
   - 부모 archive로 후손을 한꺼번에 정리하지 않는다.
   - 다른 소유자의 세션을 분리해서 정리를 가능하게 만들지 않는다.
   - "이미 보관됨" 응답은 공통 절에 따라 readback한 뒤 적용 확인으로 처리한다.
   - 그 밖의 거절이나 안전에 영향을 주는 상태 변화가 있으면 보존하고, 사유와 실제 상태를 `result.md`에 기록한다.
3. **workspace:** 구성원 단계가 모두 적용 확인된 workspace만 MCP `archive_workspace`로 처리한다. 호출 **직전에** git 상태(ignored 포함), 구성원, workspace ID 기준 터미널, teardown을 다시 읽는다. 1단계 재확인 뒤 에이전트를 처리하는 동안 바뀌었을 수 있기 때문이다. workspace archive는 구성원 archive가 하나 실패해도 계속 진행하고 디렉터리를 지울 수 있다. 그래서 구성원 확인을 먼저 끝낸다.
4. **연결이 끊긴 worktree:** 호출 직전에 git 상태(ignored 포함)와 경로 사용을 다시 읽는다. `--force` 없는 `git worktree remove`도 ignored 파일은 막지 않고 함께 지우기 때문이다. 그런 다음 `git -C <소유 저장소> worktree remove <경로>`를 `--force` 없이 실행한다. 거절되면 거기서 멈춘다. 다음 방법으로 우회하지 않는다: ignored 파일 선삭제, `--force`, `rm`, `worktree prune`.

## 결과 확인과 부분 실패

- **에이전트:** 공통 절의 readback(`Archived`·`ArchivedAt`·`ParentAgentId`)을 대상과 영향받는 후손에서 확인한다. 걸려 있던 heartbeat의 실제 상태도 확인한다.
- **workspace:** 다음을 확인한다: `list_workspaces`, 구성원 각각의 보관 상태, 터미널, 디렉터리 존재 여부.
- **worktree:** 다음을 확인한다: 경로가 없어졌는지, `git worktree list`에서 등록이 사라졌는지, 보존하기로 한 브랜치·태그가 남았는지.

성공 반환이나 목록에서 사라진 것만으로 완료 처리하지 않는다. 적용·보류·부분 실패를 나눠 기록한다.

복구하려고 archive된 세션에 프롬프트를 자동으로 보내지 않는다. 프롬프트를 보내면 unarchive되면서 새 턴이 시작되고, 후손·heartbeat·지워진 파일은 돌아오지 않는다.

## 하지 않는 것

- running이거나 대기 중인 작업을 중단하거나 kill하지 않는다.
- 다음 명령을 쓰지 않는다: MCP `archive_agent`, `--force`, `paseo delete`, `paseo worktree archive`(브랜치까지 삭제한다).
- 저장 JSON을 직접 고치지 않는다.
- 브랜치·stash·원격 브랜치를 삭제하지 않고, PR을 닫지 않는다.
- 범위를 패턴으로 잡아 `rm`이나 `prune`을 돌리지 않는다.
- 다른 감독·chief의 lane을 인수하거나 그 작업자에게 지시하지 않는다. 다른 세션에 질문을 보내지 않는다.
- completed 상태인 schedule 이력을 지우지 않는다.

  - 최신 소유자와 후임을 확인했다.
  - 해당 잔재를 포함한 명시적 완료 판정이 있다.
  - 지금 다른 감독·chief의 관리 대상이 아니다.
- **읽을 기록:** 다음 기록을 모두 본다.
  - `-chief/tasks.md`
  - chief가 직접 배정한 일반 `tasks.md`
  - 인계 뒤 현재 소유자가 가리키는 기록
- **겹칠 때:** 관리 중인 lane과 겹치면 그 lane은 제외하고, 조정이 필요하면 사용자에게 보고한다. 이 스킬만의 잠금은 따로 만들지 않는다.

**버전**

수집기와 이 문서는 Paseo 0.15.4의 다음 동작을 기준으로 한다.

- 저장 레코드 형식
- `list_agents` 필터
- archive 연쇄
- heartbeat 완료 처리
- workspace archive의 worktree 제거

데몬 버전이 다르거나 수집기가 형식 차이를 `gaps`로 보고하면, 그 동작에 기대는 판정은 판단 불가로 둔다. 동작 변경이 확인되면 이 문서와 수집기를 함께 고친다.

## 보고

보고에는 다음을 담는다.

- 실행 디렉터리 경로와 수집 시각
- A·B·C 집계와 대표 항목
- 사용자 결정이 필요한 B 표
- 실행했다면 적용·보류·부분 실패와 readback 결과
- 수집하지 못한 범위(`gaps`)

관측한 사실과 추정을 구분하고, 판단 근거로 쓴 기록의 출처를 밝힌다.
