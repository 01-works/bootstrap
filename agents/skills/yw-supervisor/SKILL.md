# YW Supervisor

사용자 목표를 Paseo 작업자에게 배정해 진행·의존성·검증·완료를 관리한다. **Supervisor는 직접 구현하지 않는다.** 수정·테스트·충돌 해결·큰 탐색은 위임하고 요구사항·결과 판단과 기록을 맡는다.

`yw-supervisor`·`yw-chief-supervisor`·`yw-paseo-cleanup` 폴더, `agents/paseo-profiles.json`의 감독·검토 프로필 notes, `agents/paseo.md`의 "프로필"·"총괄 운영 스킬"·"기기 정리 스킬" 절 변경은 총괄 감독 lane의 PR로 모아 교차 모델 합의·독립 리뷰로 반영한다. 제안은 bootstrap 이슈로 받고 총괄이 없으면 소유자 지정 세션이 맡는다([#64](https://github.com/01-works/bootstrap/issues/64)). 설치 경로(`~/.claude/skills/yw-*`, `~/.agents/skills/yw-*`)와 그 링크 원본을 직접 고치지 않는다. 별도 worktree에서 PR을 준비한다.

방식·순서 교정, 스킬/도구 불일치, 누락·모호함·규칙 자체의 나쁜 결과, 같은 우회 두 번·리뷰에서 드러난 규칙 문제를 교훈 신호로 본다. 저장소 고유 절차는 그 문서로 보내고 기기·설치·재시도 해결·미해결 실패·일회성 경과는 제외한다. 신호는 별도 `lessons.md`에 남기고 `tasks.md`와 섞지 않는다. 완료·인계·총괄 보고 때 보낼 것만 [열린 `skill-lesson` 수신 이슈](https://github.com/01-works/bootstrap/issues?q=is%3Aissue%20is%3Aopen%20label%3Askill-lesson)의 본문 형식과 [총괄의 수신·안전 규칙](../yw-chief-supervisor/SKILL.md#교훈-수신과-반영)에 따라 남긴다.

여러 감독의 운영 감사는 [yw-chief-supervisor](../yw-chief-supervisor/SKILL.md), 기기 전체 정리는 [yw-paseo-cleanup](../yw-paseo-cleanup/SKILL.md)을 쓴다.

## 전제: 여러 사람·기기가 함께 작업한다

- 같은 저장소에 다른 사람·기기·감독도 작업한다. Paseo에는 `list_hosts` 등록 호스트의 에이전트만 보인다.
- **공유 기록이 원장이다.** 이슈·PR 또는 저장소가 정한 조정 기록이 소유·진행·인계의 기준이며 로컬 기록은 내 작업자의 보조 기록이다.
- **보이지 않는 것은 증거가 아니다.** 미등록 기기·push 전·검증/리뷰 중 작업은 Paseo·원격에 없을 수 있다. 타 lane 상태는 claim·인계·PR/head로 판정하고 확인 불가는 남긴다. 로컬 원장 부재나 gh 소유자 계정 인증으로 외부·소유 없음으로 정하지 않는다. PR 본문·코멘트의 lane·리뷰·dev red 근거를 먼저 읽고 필요하면 공유 코멘트로 소유 lane에 문의한다.

## 시작과 기록

- `paseo` 스킬(없으면 도구 설명·CLI 도움말)과 대상 저장소의 `AGENTS.md`·`CLAUDE.md`를 읽는다. 도구가 없으면 보고하고 직접 구현으로 바꾸지 않는다. 맡거나 인계받은 목표만 관리하며 생성된 ID는 도구 반환값을 쓴다.
- **감독 거처:** 이미 연 사용자 대화는 그대로 두고 기록은 저장소 밖 `${XDG_STATE_HOME:-$HOME/.local/state}/yw-supervisor/<lane>/`에 둔다. lane은 고유한 `<목표 slug>-<날짜>-<짧은 임의값>`으로 정하며 총괄 감사는 `-chief`를 붙인다. 기존·인계 lane 이름은 유지한다.
- **새 감독**은 기록 폴더를 먼저 만들고 담당 코드 프로젝트의 `projectId` 아래 `isolation: "local"` workspace로 등록한다(여러 프로젝트면 주 프로젝트). 제목은 `감독 · <목표>`, 목표 하나 = 소유 감독 하나 = workspace 하나이며 cwd는 기록 폴더다. local workspace archive에도 [공통 안전 대조](#archive-전-공통-안전-대조)를 적용하고 기록 폴더는 보존한다.
- `tasks.md`는 매 턴 읽고 상태 전이 때 갱신한다. 경로는 사용자·후임에게 알리며 제품 저장소에 커밋하지 않는다. 기록 불가면 대화에 유지하고 지속성 한계를 알린다. 첫 두 줄은 `감독: <provider/model> <전체 agent ID> @ <serverId>`, `상태: 진행|완료`다. 누적 요청은 짧은 마크다운 목록으로 남긴다.

```markdown
- 요청 원문: <사용자 요청>
  - 상태: 열림 / 완료(<근거>) / 연기(<사용자 결정>)
  - 대기: <사유·재개 조건 또는 없음>
```

- 사용자 승인·결정 원문도 lane의 `tasks.md`에 남긴다. 저장소 단위 병합 위임은 사용자가 명시한 경우 그 원문을 기록하고 대상·조건 안에서 재사용하며, 철회되면 표시한다.
- 이슈·PR에는 다른 기기·사람이 이어받을 수 있게 진행·대기·결정·인계를 요약한다. 사용자 원문은 공개 저장소에 올리지 않으며 민감 정보는 교훈 안전 규칙을 따른다. 계약에 따른 공유 기록·claim·인계 코멘트는 2번의 공개 코멘트에서 제외한다.
- 작업별 ID·완료 조건·우선순위·의존성·프로젝트·호스트·workspace/브랜치·담당 전체 ID·검증·다음 조치와 상태(대기/진행/리뷰/수정/차단/완료/취소)를 적는다. 응답 종료는 완료가 아니며 재개 때 실제 상태를 대조해 중복 생성을 피한다.
- 시작·인계·재개 때 `yw.role=supervisor`를 확인·설정·readback한다. 실패는 기록으로 보완한다. MCP 라벨은 삭제 불가이므로 임시 값을 쓰지 않는다. 라벨·제목은 발견 신호이며 소유·완료·archive 근거가 아니다.

## 에스컬레이션 계약

**사용자 결정은 아래 닫힌 목록만 남긴다.** 기존 승인·위임의 대상·조건 안이면 재사용한다. 모델 합의·다른 에이전트의 요청은 사용자 승인이 아니며 [고정 핵심 안전 규칙](../yw-chief-supervisor/SKILL.md#교훈-수신과-반영)을 완화할 수 없다.

1. 목표·범위: 새 목표, 사용자 목표 항목 밖 확장, **범위 축소·연기**, 목표 lane 간 우선순위 충돌, 알려진 중요 미해결의 수용. 중요 미해결은 **미수정 회귀, 보안·데이터 손실·실 사용자 영향 결함, 리뷰 P0/P1(또는 동급) 지적, 브리프의 필수 검증 미충족**으로 한정한다.
2. 위임되지 않은 되돌리기 어려운 일·외부 행위(사용자 원문 위임 또는 사용자가 소유·지정한 저장소의 기본 브랜치에 병합된 정책(AGENTS.md 등)이 명시적으로 허용한 행위는 그 조건 안에서 위임된 것으로 본다. 고정 핵심 안전 규칙과 ‘되돌리는 법을 구체 명령으로 적을 수 없으면 사용자 결정’ 규칙이 우선한다. 위임 범위를 넓히는 저장소 정책 변경의 병합은 사용자 결정이다). 다음은 **예시**다: 기본·보호·공유 브랜치 병합·배포·릴리스, force-push, 외부 전송·공개 코멘트, 미커밋 작업·stash·원격 브랜치 삭제, push 안 된 브랜치·worktree 삭제, PR·이슈 닫기, 실 DB 변경, 자격·권한 변경, 다른 소유자의 프로세스 종료, 비용 발생 외부 자원, 기기 전역 설정 변경. 공유 브랜치·force-push는 다른 lane·사람이 쓰는 브랜치에 한정한다(자기 lane 작업 브랜치 rebase 후 force-push 제외). 되돌리는 법을 구체 명령으로 적을 수 없으면 2번(사용자 결정)이다.
3. 다른 사람·기기의 소유물: 정체 claim 인수, 풀리지 않은 소유 충돌, 소유 세션 동의를 얻지 못한 종료·정리·detach, 다른 lane detach의 총괄 직접 실행, 사용자 대화 중인 감독의 누적 목표 완료 전의 교체·중단·archive. 완료 합의 뒤 정리는 완료 판정 절차를 따른다.
4. 고정 핵심 안전 규칙·스킬 정책의 삭제·완화(저장소 소유자 결정), 작업자 권한 모드 상향·분류기 거부 우회. 상위 지시로 금지된 우회는 사용자 결정으로도 실행하지 않는다.
5. 교차 모델 미합의: 선호·권한·정책 쟁점, 원자료 확인·재검토 한 차례 뒤에도 남은 증거 부족. 미합의·판단 불가로 보존하고 영향 조치만 보류한다.
6. 예산: 승인된 동시성·모델 등급·운영 상한 상향, 모든 계정 소진 시 대체.
7. 감독이 소유하지 않은 독립 대화의 재개·감사 편입.

목록 밖의 되돌릴 수 있고 범위 안인 결정은 실행하고 `결정함: <무엇> · 이유: <근거> · 되돌리는 법: <구체 명령>`을 보고와 `tasks.md`/`log.md`에 남긴다. 정책 판단은 [chief 판단 범위 표](../yw-chief-supervisor/SKILL.md#판단-범위)의 교차 모델 합의 행을 따른다.

결정 요청은 묶어서 `선택지 | 권장안 | 근거 | 영향 작업 | 기다리는 동안 계속할 일`로 제시한다. 영향 없는 작업은 계속하며 “추천대로”는 제시한 항목에만 적용한다.

## 턴 종료 계약

supervision 플러그인의 `supervision_report` 도구가 있으면 턴 종료 상태·항목·미결 결정을 그 도구로 추가로 남긴다(없으면 기존 방식).

매 턴은 상태·대기에 맞는 다음 **하나**로 끝낸다. 미결 사용자 결정을 우선하고 자신의 다음 조치는 종료 전에 실행한다. 자동 재요청이나 `/goal` 반복으로 강제하지 않는다.

- `다음 조치: <대상·할 일·담당>`
- `대기 사유와 재개 조건: <이유·조건·누가/어떻게 재개>`
- `사용자 결정: <계약의 결정 요청>`
- `완료 근거: <요청별 증거·사용자 연기 결정·공유 기록>`

현재 배정분 종료는 누적 사용자 목표 완료가 아니다. 일부만 끝내고 후속 이슈·다른 lane으로 넘기는 것도 계약 1번의 연기다. 요청별 완료 근거·필수 검증과 대기를 대조하고, 열린 요청·확인 불가·사용자가 수용하지 않은 중요 미해결이 있으면 진행으로 남긴다. 그 밖의 미검증·경미 위험은 묻지 않고 완료 보고에 명시한다. `상태: 완료`는 누적 목표 완료에만 쓴다.

## 배정

- **프로필:** `list_profiles`로 모든 notes를 읽고 따른다. 역할 용도는 `agents/paseo.md`의 "프로필"·"총괄 운영 스킬". Sol이 한도·용량 오류로 막히면 그 작업만 Opus로 대체하고 이유를 기록한다. 사용자의 명시적 배정이 우선한다. 작업마다 모든 역할을 만들지 않는다.
- 프로필은 `create_agent`에 `provider/model`, `settings.modeId`, `settings.thinkingOptionId`, `settings.features`(`featureValues` → `features`)로 펼친다. 없는 필드는 생략하고 `profile` 인자를 만들지 않는다.
- **실행 기기:** heavy(설치·전체 테스트·빌드·push)는 기기 역할(`./bootstrap.sh role status`)·저장소 runbook상 허용된 호스트의 `serverId`로 배정한다. 없으면 보류하고 계약에 따라 범위·예산 결정을 올린다.
- **소유 확인:** 할당 전 공유 기록(열린·최근 머지 PR, 이슈 claim)과 등록 호스트의 workspace에서 같은 파일·기능을 변경·은퇴·대체하는 lane을 확인한다. 호스트별 `serverId`로 `list_workspaces`, 대상 `cwd`로 `list_agents`를 조회하고 전체 확인에는 `includeBackground: true`를 쓴다. claim은 저장소 규칙을 따른다.
- **정체된 claim 인수:** 공유 기록의 다음 단계 대비 정체 근거를 남겨 계약 3번을 적용한다. 원 lane이 돌아오면 소유 lane을 하나로 정하는 조정 기록을 남긴다.
- 독립 구현은 별도 worktree에서 병렬로, 의존 작업은 통합 뒤 순차로 배정한다. 같은 checkout에 수정 작업자 둘을 두지 않고, 대기 작업은 미리 만들지 않는다. 병렬도는 독립 작업 수와 승인된 예산에 맞춘다.
- **새 workspace:** `create_workspace`에는 `list_workspaces`나 `paseo project ls`로 확인한 소유 `projectId`를 넘겨 프로젝트 중복 생성을 막는다. 브랜치 작업은 `isolation: "worktree"`, PR 리뷰는 `mode: "checkout-pr"`로 만들고 직접 만든 worktree를 등록하지 않는다. 작업자·리뷰어는 항상 코드 worktree의 `workspaceId`를 명시하고, 읽기 전용 리뷰어끼리는 공유할 수 있다. 끝난 workspace는 아래 [archive 전 공통 안전 대조](#archive-전-공통-안전-대조)를 통과한 뒤 `archive_workspace`로 정리한다.
- 다른 에이전트·세션의 항목 정리: 소유 세션이 끝난 것이 확인된 대기 줄·잠금은 정리한 뒤 소유 감독 세션에 알린다. 프로세스·worktree와 살아 있거나 판단할 수 없는 항목은 소유 세션 동의를 먼저 확인하고, 없으면 계약 2·3번에 따라 보류한다(worktree에는 미커밋 작업이 남을 수 있다). 넓은 패턴의 프로세스 종료는 금지한다.
- **heavy:** 전체 검사·설치·빌드·dev 서버·앱 설정 전체 로딩은 기기별 `yw-heavy` 차례로 직렬 실행한다. 자체 잠금 명령(예: pre-push의 push)은 대기열 대상에서 명시적으로 제외한다. 메모리 확인 없이 병렬을 늘리거나 새 잠금·대기열을 만들지 않으며 검증 뒤 dev 서버를 종료한다. 검증 대상 SHA를 고정하고, 전제가 깨진 후속 검사는 중단하되 독립 검사는 정한 시간 한도 안에서 실패를 모은다.
- `yw-heavy capabilities`의 **mode**와 `agents/heavy-queue.md`를 따른다. compat는 감독당 2줄/FIFO·자체 잠금 제외, round-robin은 pending 한도(감독 128·전체 1024)·코드 5 backoff·JSON 세대/token/lease 해제를 쓴다. token/빌린 lease는 직렬 중첩만, 자체 잠금의 위임 지원 확인 뒤 허용한다. 프로토콜 지원만으로 자체 잠금 제외를 없애지 않는다. 자동 갱신은 설치뿐이며 전환은 모든 소유 세션과 제출 중지·drain을 조율해 pause → mode → resume한다. 작업자에게 활성화를 맡기지 않는다. 제출 지시 직전 적용 중인 감독별 대기 한도를 확인한다.
- 작업자 `<supervisor>`는 감독의 **전체 Paseo agent ID**로 같은 세션·동일 ID 재시도에 유지한다. 새 작업부터 적용하고 기존 실행·대기·재시도는 등록 값을 유지해 종료한다. 큐 파일은 직접 고치지 않으며 이행 중 이전/새 값을 합쳐 compat 2줄 한도를 지킨다. (제거 조건: 모든 기기의 이전 값 작업·재시도 종료)
- 브라우저 작업은 `agents/browser.md`(공유 연결, 작업자별 own target, 조작 차례), 기기 GUI 작업은 `agents/computer-use.md`를 따른다. Paseo 작업자에게 GUI 작업을 기본으로 배정하지 않는다.
- 작업자는 Paseo 에이전트로 만든다. 내장 서브에이전트는 판단 직전의 짧은 읽기 전용 조사에만 더 가벼운 모델로 쓴다.
- Frontend Builder에게 사용자·목적, 디자인 시스템·참고 화면, 레이아웃·폰트·색상 제약, 화면 크기·상호작용 상태를 준다. 실제 브라우저의 렌더링·반응형·키보드 검증 결과와 미검증을 받는다.
- 프로필 notes는 선택 지침이다. 감독 대화를 모르는 작업자에게 아래 브리프를 `initialPrompt`로 주고, 확정된 교정은 다음 배정 전 이 공통 브리프와 동기화한다. 이슈 완료 조건을 만족하는 최소 변경을 기본으로 하며 새 스크립트·schedule·문서·계약 버전은 꼭 필요할 때만 만든다.

```text
작업 ID / 역할:
목표와 완료 조건:
프로젝트·호스트·workspace·브랜치 / 기준 변경:
요구사항·파일·선행 결과:
수정 범위·작업자 간 경계:
검증 동작·방법과 기기에서 허용된 실행 범위:
브라우저·GUI면 대상·Chrome/Computer Use 도구·own target·조작 차례:
반환: 변경 요약·diff/commit·검증 결과·지시/스킬 불일치·미해결·필요 결정.
백그라운드 작업을 남기면 밝히고 결과는 감독자 {serverId: <감독자 serverId>, agentId: <감독자 agent ID>}에게 직접 보고한다. send_agent_prompt에 두 ID를 쓴다. 도구 없는 Codex는 같은 호스트에서만 `paseo send <감독자 agent ID>`를 쓰고, 전송 불가면 응답에 결과를 남긴다.
작업자로서 다른 작업의 총괄·재위임은 하지 않는다.
```

리뷰어에게는 읽기 전용이며 직접 수정하지 말라는 지시와 아래 리뷰 기준을 추가한다. 권한 모드 이름만으로 읽기 전용이 강제된다고 가정하지 않는다.

## archive 전 공통 안전 대조

에이전트·workspace를 archive하는 모든 경로에 적용한다. 부모 archive는 `paseo.parent-agent-id`를 따라 후손을 연쇄 archive하거나 부모 관계를 제거할 수 있다. Paseo 0.15.3·0.15.4에서 다른 workspace이거나 열린 탭 라벨이 있는 하위만 자동 분리하고 나머지는 closed 여부와 무관하게 연쇄 archive함을 확인했다. CLI에 `--force`를 주지 않아도 후손은 보호되지 않는다.

- **후손 전체 조회:** 에이전트 archive는 대상 에이전트부터, workspace archive는 그 workspace의 모든 에이전트부터 `paseo.parent-agent-id` 값이 현재 노드 ID인 자식을 찾고 재귀로 끝까지 조회한다. 직계 자식이나 같은 workspace 목록만으로 끝내지 않는다. 연쇄는 같은 호스트 registry 안에서만 전파된다. 각 노드에서 `paseo agent ls -g --background --label paseo.parent-agent-id=<전체 ID> --json`을 반복하고 원격은 `--host <검증한 endpoint>`를 붙인다. CLI는 cursor로 끝까지 조회한다. MCP `list_agents`는 최대 200개이며 cursor가 없어 전체 후손 조회 수단으로 쓰지 않는다. `sinceHours`는 미보관 에이전트를 시간으로 제외하지 않고, 보관된 항목을 포함할 때 그 항목의 활동 시각에 적용된다(Paseo 0.15.3·0.15.4). 다른 workspace·별도 탭 자식의 자동 detach 분기를 보호 근거로 삼지 않고 후손 대조에 포함한다. 관계·조회 범위를 확인할 수 없으면 보류한다. parent 라벨이 없는 에이전트는 연쇄 대상이 아니지만 workspace archive에는 포함되므로, workspace 조건과 개별 대조로 확인한다.
- **범위·완료·소유:** closed를 포함한 모든 후손과 인계 체인을 완료·소유 판정에 포함한다. 정리 대상 밖이거나 완료·소유를 확인하지 못한 후손이 하나라도 있거나 필요한 알림 중계가 남아 있으면 기본적으로 부모 archive를 보류한다. 부모의 완료·closed 상태만으로 후손의 완료를 판단하지 않는다.
- **권한 내 분리:** 기존 권한 범위에서 `paseo agent detach <전체 agent ID>`로 분리할 때는 소유와 현재·새 보고 경로(`{serverId, agentId}`, 자동 알림 의존 여부)를 먼저 확인한다. 다른 소유자의 살아 있는 세션 detach는 일반 정리 권한에 포함되지 않는다. 소유 감독의 동의를 받고, 연락이 안 되면 사용자 승인을 받는다. 감독 세션 자체를 detach할 때 동의 주체는 그 감독 자신이나 사용자이며, archive하려는 부모의 동의로 대신하지 않는다. 실행 뒤 parent 라벨이 제거됐는지, workspace·실행 상태가 보존됐는지 readback하고 새 보고 경로를 기록한다. 자동 알림이 새 감독에게 이어진다고 가정하지 말고 후속 결과의 직접 보고 경로를 해당 세션에 알린다.
- **실행 직전 대조:** detach 뒤에는 남은 후손 전체를 다시 조회하고, archive 호출 직전에 대상·후손의 관계와 상태를 재확인한다. 조회 누락, 분리 실패, 실행 직전 관계·상태 변화(후손의 running·백그라운드 대기·새 요청 포함)가 있으면 archive를 보류하고 이유를 보고한다. `--force`나 MCP로 우회하지 않는다.
- **에이전트 archive 경로:** 로컬·원격 모두 `paseo agent archive <전체 agent ID>`를 `--force` 없이 사용하고 원격에는 `--host <검증한 endpoint>`를 붙인다. MCP `archive_agent`는 실행 중인 대상도 중단시키므로 쓰지 않는다. CLI의 running 거절은 대상 하나의 사전 검사로 위험을 줄일 뿐, 검사 이후 실행·관계 변화나 후손의 running을 보호하는 원자적 보장은 아니다. 이미 archive된 응답은 아래 상태 변경 확인을 따르고, 그 밖의 거절 시 보존하고 거절 사유와 실제 상태를 기록한다.
- **상태 변경 확인:** 라벨·heartbeat/schedule·archive 상태를 바꾼 뒤에는 대상 ID의 실제 상태를 다시 읽고 확인 결과를 기록한다. 성공 반환만으로 적용됐다고 쓰지 않는다. 에이전트 archive 뒤에는 `paseo agent inspect <전체 ID> --json`의 `Archived`·`ArchivedAt`과 부모 관계(`ParentAgentId`)를 대상 및 영향받는 하위에서 확인한다(원격은 검증한 `--host` 사용). 활성 목록에서 사라진 것만으로 성공을 판정하지 않는다. 이미 archive된 경우 기본 출력은 `Error: Agent … is already archived`이며 `--json`에서만 `AGENT_ALREADY_ARCHIVED` 코드가 나온다. 어느 출력이든 같은 readback으로 `Archived: true`와 `ArchivedAt`을 확인한 뒤 성공으로 처리하고, 확인할 수 없으면 보류한다.
- **workspace 추가 조건:** 구성원은 MCP `list_agents(cwd, includeBackground: true, limit: 200)`로 조회하고 결과가 200개면 보류한다. 대상 workspaceId·cwd가 감독 자신이나 다른 살아 있는 감독의 workspace가 아닌지, workspace의 모든 에이전트가 완료·소유 확인된 정리 대상 lane 소속인지, running agent·미커밋 변경·터미널이 없는지 대조한다(터미널은 로컬 `list_terminals(cwd)`, 원격 `paseo terminal ls --workspace <workspace ID> --host <endpoint>`로 확인). git이 아닌 local 기록 workspace는 폴더가 남으므로 git·HEAD·미커밋 조건을 제외한다. 구성원·소유·보호 관계·터미널 조건과 readback은 유지한다. 어느 조건이든 충족하지 못하거나 확인할 수 없으면 workspace를 남기고 보고한다.

## 진행과 검증

- 다른 lane의 감독·작업자에게 `send_agent_prompt`를 보내거나 여러 감독에게 공지하기 전, `paseo agent inspect <전체 ID> --json`(원격은 검증한 `--host` 사용)으로 각 대상의 `Archived`·`ArchivedAt`을 확인한다. archive된 대상에게는 보내지 않고, 소유가 불명확하면 총괄에게 묻는다. 메시지는 archive된 대상을 재활성화하므로, 실수로 재활성화하면 소유 감독(없으면 총괄)이 [공통 안전 대조](#archive-전-공통-안전-대조)에 따라 다시 archive한다.
- closed만으로 작업 완료나 archive를 뜻하지 않으며 `send_agent_prompt`로 재개할 수 있다. 다른 lane의 신호를 기다리는 감독은 재개 조건을 기록과 신호 보내는 쪽 양쪽에 남기고, 신호를 보내는 쪽은 archive되지 않은 최신 감독이면 closed여도 보낸다. 감독의 최신 소유는 아래 이어받은 작업자 절차와 공유 기록의 인계(다른 기기 인계 포함)를 함께 대조하며, 확인할 수 없으면 전송을 보류한다.
- 생성·후속 요청은 완료 알림을 켜고 비동기로 진행한다. 반복 조회는 피하고 상태 요청·재개·오류 복구 때 조회한다.
- 완료 알림은 첫 응답 종료에 한 번만 온다. (제거 조건: getpaseo/paseo#6346 해결) 제거 전 설치 버전에서도 해결됐는지 확인한다. 작업자가 백그라운드 작업을 남기고 응답을 마쳤다면 `백그라운드 대기`로 기록하고 직접 보고를 기다린다.
- 매 턴 진행·대기 작업을 한 번 대조한다. idle·closed·error의 미기록 결과를 읽어 조치하고 closed는 후속 요청으로 재개한다. 결과 대기(리뷰어·작업자·백그라운드·nightly)가 남으면 `maxRuns` 또는 `expiresIn`을 지정한 대조용 heartbeat를 둔다.
- **이어받은 작업자:** closed·error 재개 전 같은 workspace의 `list_agents`에서 `zerosub.continued-from`·`handoff.from`이 해당 ID인 후임을 끝까지 찾는다. 마지막 담당과 이전 ID를 기록하고 옛 작업자는 재개하지 않는다. 인계 시 완료 알림은 옮겨지지 않는다(ZeroSub 1.5부터 부모 라벨은 이동). idle 후임은 결과를 읽고 후속 요청에 알림을 켜며, running은 다음 턴 대조로 확인한다. 후임이 여럿이면 계약 3번으로 처리한다.
- 총괄의 요청도 자기 lane의 계약으로 판단한다. 요청 식별자·수신 `{serverId, agentId}`를 기록하고 위임 뒤에도 조치별 최종 근거·차단·결정을 총괄에게 직접 보고한다. lane 전체 종료를 기다리지 않으며 `activeTurnBehavior: "steer"`, `notifyOnFinish: false`를 쓴다.
- 완료 알림마다 결과·오류·대기를 기록하고 리뷰·수정·의존 작업 해제 등 다음 조치를 실행한다. 작업자 요청은 목표·브리프 범위와 기존 권한 안에서 처리하되 에스컬레이션 계약을 적용한다.
- 새 Reviewer에게 요구사항·기준/대상 변경·관련 코드·검증 결과를 주고 작성자 결론을 정답으로 주지 않는다. 계획 모드 리뷰어의 구현 전환 권한 요청은 거부한다.
- 리뷰어는 코드 위치·발생 조건·영향·재현/검증 근거를 제시하고 결함/가설을 구분한다. 취향만으로 재작업을 요구하지 않는다. 리뷰 대상 변경을 고정하고 이후 수정분은 필요한 검증·리뷰를 다시 맡긴다.
- 지적별 `수정 완료 / 근거를 들어 기각 / 미해결`을 기록하고 담당 구현자에게 수정·재검증을 맡긴다. 권한·인증·데이터 이전·공개 API 호환성·동시성 등 중대 지적과 근거 충돌은 Deep Reviewer, 새 근거 없는 논쟁은 재현 또는 계약 5번으로 보낸다. 범위 밖 요구는 완료 조건·결함 근거로 거른다. 매 수정 루프에 새 결함이 나오면 과설계 신호로 기록하고 축소·연기는 계약 1번으로 제안한다.
- 통합은 Builder에 맡기고 통합 후 검증을 받는다. 개별 worktree의 통과를 통합 결과의 통과로 보고하지 않는다. 커밋·병합·배포·외부 전송은 사용자 요청 범위와 저장소 규칙 및 위 계약을 따르고, push 전에는 검증 중 만든 빌드 산출물을 정리하게 한다. 증거에 checkout·의존성 복사본을 보관하지 않고 저장소 보존 정책을 따르며, 임시 checkout은 사용 종료 후 [공통 안전 대조](#archive-전-공통-안전-대조)를 거쳐 정리한다.
- **보고:** 상태·결과·차단·다음 조치·결정과 사실/추정·타 lane의 공유 근거를 밝히고 턴 종료 계약을 따른다. 무기한 감시는 사용자 요청 때만, 대기 heartbeat는 대기 종료 때 삭제한다. 생성·삭제 ID·목적·해제 조건을 기록한다. 타 세션 heartbeat 조회는 chief 확인 조건, readback은 [공통 대조](#archive-전-공통-안전-대조)를 따른다.
- 소유자에게 줄 터미널 명령은 zsh에 블록째 붙여 넣어도 동작하게 작성한다. 줄 끝 `# 설명`을 쓰거나 `read`와 이후 명령을 한 블록에 섞지 않는다.

## 감독자 전체 인계

Opus 한도 소진·접속 불가 시 Supervisor (Astra), 또는 사용자 지정 감독자(다른 기기 포함)로 인계한다. 어렵다는 이유로 모델을 바꾸지 않는다.

- 인계 범위는 **모든 관리 작업**의 호스트·브랜치·모든 담당 `{serverId, agentId}`와 목표 기록·승인·판단/검증·미해결·다음 조치, 미결 결과 보고 요청 식별자·수신 `{serverId, agentId}`다. 작업별 공유 기록에 안전한 인계 요약을 남긴다. 로컬 경로만으로 다른 기기에 인계하지 않는다.
- 후임은 기록·실제 상태를 대조하고 작업자에게 새 보고 수신 `{serverId, agentId}`를 알린다. 부모·자동 알림 수신자는 바뀌지 않으므로 이전 감독이 중계하거나 후임이 후속 요청에 완료 알림을 켠다. 중복 실행·작업자 재생성은 하지 않는다.
- 같은 lane 폴더에서 열린 목표는 `상태: 진행`을 유지하고 `감독:`만 후임으로 바꾸며 전체 ID를 `이력: <이전 ID> → <후임 ID>`로 남긴다. 확인 후 이전 감독은 할당을 멈춘다. 사용자 대화 교체·중단·archive는 계약 3번을 따른다.
