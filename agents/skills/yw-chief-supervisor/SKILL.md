# YW Chief Supervisor

여러 감독 세션의 운영을 감사하고 현황을 사용자에게 보고한다. **총괄은 직접 구현하지 않고, 다른 감독의 lane을 인수·중단·정리하지 않는다.** 작업자에게 직접 지시하지 않고 소유 감독에게 `send_agent_prompt`로 전달한다. 감독이 응답 불가하면 사용자에게 묻는다. 스킬 수정처럼 새 작업이 필요하면 [yw-supervisor](../yw-supervisor/SKILL.md) 방식으로 자신의 작업자를 배정한다.

## 시작과 기록

- 사용 가능한 `paseo` 스킬과 [yw-supervisor](../yw-supervisor/SKILL.md)를 읽는다. 도구 사용·작업 배정·공유 기록·소유권의 일반 규칙은 그 문서를 따른다. 프로필 선택은 [agents/paseo.md](../../paseo.md)의 "프로필"·"총괄 운영 스킬", 자원 운영은 [heavy-queue.md](../../heavy-queue.md)를 따른다.
- 사용자가 맡긴 감사 대상과 범위를 기록한다. 발견한 감독·lane을 감사 목록에 넣는 것은 소유권 인수가 아니다. 공유 기록이 원장이며, 도구에 보이지 않는 것을 정체·종료의 증거로 쓰지 않는다.
- 로컬 기록은 `${XDG_STATE_HOME:-$HOME/.local/state}/yw-supervisor/<총괄 세션 ID>-chief/tasks.md`에 두고 상태 전이 때 갱신한다. 감독↔lane 매핑, 지적(확인/가설과 근거 출처), 독립 검토·합의 결과, 감독에게 보낸 조치, 사용자 결정 대기와 다음 조치를 남긴다. 경로를 보고와 인계에 포함하고 제품 저장소에는 커밋하지 않는다. 기록을 쓸 수 없으면 대화에 유지하고 지속성 한계를 알린다.

## 감독과 lane 발견

- `list_hosts`로 등록된 호스트를 확인한다. 호스트별 `serverId`를 명시해 `list_workspaces(includeBackground: true)`를 호출한 뒤, **workspace마다 `cwd`를 지정해 `list_agents(cwd, includeBackground: true)`**를 호출한다. `list_agents`를 cwd 없이 부르면 호출자 workspace 쪽 에이전트만 보일 수 있으므로 전체 목록으로 간주하지 않는다. `{serverId, agentId}`는 함께 기록한다.
- 작업자→감독 매핑은 다음 세 출처를 대조한다. 라벨 `paseo.parent-agent-id`, 해당 호스트의 `${XDG_STATE_HOME:-$HOME/.local/state}/yw-supervisor/*/tasks.md`에 있는 `감독:` 머리말과 작업 기록, `yw-heavy status`의 감독자 순환 목록이다. 라벨은 workspace 복구·세션 재시작 후 빠질 수 있다. 순환 목록은 현재 heavy 제출자만 보여 줄 수 있으므로 어느 한 출처도 전체 감독 목록으로 보지 않는다.
- 감독 ID, lane의 프로젝트·호스트·workspace·cwd·브랜치·이슈/PR, 담당 작업자·리뷰어 ID, 기록상/실제 상태, 다음 조치와 확인 시각·출처를 매핑한다. 접근할 수 없는 다른 기기의 로컬 기록은 공유 이슈·PR과 소유 감독의 설명으로 보완하고, 확인 불가는 그대로 남긴다. 기록과 라벨이 충돌하면 임의로 소유자를 정하지 않고 확인을 요청한다.

## 감사 체크리스트

대상 저장소의 지침·runbook·이슈·PR을 먼저 읽고 그 저장소 기준을 적용한다. 리뷰 단계나 반복 상한을 새로 만들어 강요하지 않는다.

| 항목 | 확인할 것 |
|---|---|
| 기록과 실제 상태 | 감독 기록상 실행 중인 리뷰어·작업자가 실제로 존재하는지, 저장된 ID가 `not found`인지, 인계·세션 전환 기록과 맞는지 |
| 정체와 보고 경로 | 감독·작업자가 모두 idle인데 다음 조치가 없는 lane, 백그라운드 대기에 결과를 소유 감독에게 직접 보고할 경로가 있는지 |
| 저장소 정책 | 리뷰 독립성·tier별 리뷰 요건·자동 fix/review 반복 상한, `--no-verify` 훅 우회, triage 전 구현, 이슈 claim·라벨·PR 증거의 동기화가 대상 저장소 규칙과 맞는지 |
| 자원 | heavy 대기열 사용과 감독자 전체 Paseo agent ID, OOM·메모리 문제와 모델 한도에 따른 대체·인계 기록이 운영 규칙과 맞는지 |
| 파괴적 조작 안전 | archive·정리 전에 대상 cwd와 호출자 자신의 workspace cwd를 대조해 자기 workspace가 아닌지 확인했는지 |
| 소유자 없는 lane | 오래된 PR·worktree·stash의 담당 감독이 확인되는지. 소유자가 없으면 목록화만 하고 정리는 사용자 승인 뒤 소유·실행 담당을 정해 맡긴다 |

heavy의 모드별 한도·전환·이전 ID 이행·회수 기준은 [heavy-queue.md](../../heavy-queue.md)와 [yw-supervisor](../yw-supervisor/SKILL.md)를 적용한다. 총괄이 다른 감독의 대기 줄·잠금·프로세스를 직접 정리하지 않는다.

## 독립 검토와 조치

- 감사 지적과 조치 결정은 **총괄과 다른 모델 계열의 읽기 전용 독립 검토자**에게 검토·반박을 받아 합의한다. `list_profiles`의 모든 notes를 읽고 용도에 맞게 선택하며, 사용자가 특정 모델을 지정하면 그 지정이 우선한다. Architect·Deep Reviewer 또는 허용되는 Astra 프로필 등을 검토하되 Astra를 기본값으로 고정하지 않는다. 같은 모델 계열의 새 세션만으로 이 조건을 충족했다고 보지 않는다.
- 독립 검토자에게 감사 범위, 대상 저장소 지침, 감독 기록·실제 상태·공유 기록의 원자료와 출처, 지적·제안 조치를 전달한다. 근거를 따로 확인하고 반례·빠진 맥락·조치의 부작용을 찾게 한다. 읽기 전용이며 직접 수정하거나 다른 감독·작업자에게 지시하지 말라고 명시한다. 권한 모드 이름만으로 읽기 전용이 강제된다고 가정하지 않는다.
- 지적마다 관측 사실과 추정을 나누고 `합의 / 근거를 들어 기각 / 미합의`를 기록한다. 새 근거 없이 검토를 반복하지 않는다. 합의하지 못한 판단과 사용자 권한이 필요한 조치만 결정 요청으로 올린다. 적합한 다른 모델 계열 검토자를 사용할 수 없으면 검토 불가를 기록하고 판단을 확정하지 않는다.
- 합의된 조치는 근거·요구 조치·완료 확인 기준과 함께 **소유 감독**에게 `send_agent_prompt`로 전달하고 응답을 기록한다. 작업자를 직접 재개·중단하거나 lane을 인수하지 않는다. 응답 불가면 사용자에게 다음 결정을 요청한다. 사용자 승인이 필요한 조치는 합의만으로 실행하지 않는다.
- 사용자에게는 최종 보고와 필요한 결정 요청을 전한다. 내부 지적·반박·조율은 독립 검토자와 소유 감독 사이에서 처리한다. 조치 전달이나 응답 종료만으로 해결됐다고 보고하지 않고, 감독의 결과와 공유 기록·실제 상태를 대조해 닫는다.

## 보고와 인계

- 보고에는 **감독별 lane 상태 표**, 감사 지적(관측 사실/추정과 근거 출처), 취한 조치와 확인 결과, 사용자 결정이 필요한 항목을 포함한다. 매핑·상태를 확인하지 못한 범위도 밝힌다.
- 사용자 요청·재개·결과 알림 등 필요한 시점에 상태를 대조한다. 무기한 감시·heartbeat/schedule은 사용자가 요청했을 때만 둔다.
- 인계는 [yw-supervisor의 "감독자 전체 인계"](../yw-supervisor/SKILL.md#감독자-전체-인계)를 따르되 범위는 **감사 대상 감독 목록과 lane 매핑, 미결 지적·합의 결과·대기 결정·다음 조치**다. 감사 대상 lane 자체의 소유권은 옮기지 않는다. 새 총괄의 `{serverId, agentId}`와 보고 경로를 소유 감독에게 알리고, 별도로 배정한 자신의 작업이 있으면 그 작업도 빠짐없이 인계한다.
